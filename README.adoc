= Prohelp CLI bridges

CLI framework bridges for Prohelp (arsd.cli and related routers).

link:https://github.com/openshellorg/prohelp-cli/issues[Request Feature]

== About The Project

**prohelp-cli** connects link:https://github.com/openshellorg/prohelp[Prohelp] (progressive *help*) to command-line *application* frameworks (parsing, routing, subcommands).

* **prohelp** — help engine, specification, preview tool, global `help` binary, C-oriented library core
* **prohelp-cli** — bridges that wire Prohelp into D CLI routers (and future adapters)

This package is a **library**. Your app is the binary. CI builds a small **`prohelp-cli-demo`** executable for regression testing.

=== Config Lifecycle Management

CLI authors who load user/project config should scan keys with
link:https://github.com/openshellorg/config-lifecycle[`config-lifecycle`]
(re-exported as `prohelp_cli.config_keys`).
Never drop detection of expired keys — see the
link:https://docs.opensh.org/open-shell-org/standard-config-lifecycle-management.html[SOS protocol].

Demo smoke: `prohelp-cli-demo check-config` (requires sibling checkout of `config-lifecycle`).

== Usage

=== Quick start (D + arsd.cli)

[source,d]
----
import arsd.cli;
import prohelp.intercept;

class App {
    void create(string[] files) { /* ... */ }
}

int main(string[] args) {
    if (prohelp.intercept(args)) return 0;
    return runCli!App(args);
}
----

=== Demo binary

[source,shell]
----
dub build -c demo
./prohelp-cli-demo ?
----

=== When to use what

| Goal | Use | Not
| Progressive help only, C/BetterC | link:https://github.com/openshellorg/prohelp[prohelp] library | prohelp-cli
| New D CLI with subcommands | **prohelp-cli** + link:https://opendlang.org/library/arsd.cli.html[arsd.cli] + prohelp | Raw intercept only
| Author/preview help.sdl | `prohelp` executable from prohelp repo | —
| Global `help <command>` on PATH | `help` binary from prohelp | —
| Python/Rust/Go CLI | Prohelp via FFI + your framework | prohelp-cli (D-only bridges)
