= Prohelp CLI bridges
Open Shell Organization <https://github.com/openshellorg>
:toc:
:homepage: link:https://github.com/openshellorg/prohelp-cli[openshellorg/prohelp-cli]

**prohelp-cli** connects link:https://github.com/openshellorg/prohelp[Prohelp] (progressive *help*) to command-line *application* frameworks (parsing, routing, subcommands).

Moved with Prohelp into OpenShellOrg (scaffold previously under Dev-Centr).

There is no widely agreed term for “library that builds CLI tools” versus “program that *is* a CLI.” In OpenShellOrg naming:

* **prohelp** — help engine, specification, preview tool, global `help` binary, C-oriented library core
* **prohelp-cli** — bridges that wire Prohelp into D CLI routers (and future adapters)

**Why no “product” binary?** This package is a **library**. Your app is the binary. Users who want a standalone help tool install `help` / `prohelp` from the prohelp repo. CI still builds and releases a small **`prohelp-cli-demo`** executable so the bridge is regression-tested and downloadable.

If you are starting a new D command-line tool, **use a CLI framework here plus Prohelp** — not the raw `prohelp.intercept` call alone unless you have a good reason (minimal C embed, custom router, prototype).

== When to use what

[cols="1,2,2"]
|===
| Goal | Use | Not

| Progressive help only, C/BetterC, existing argv parser | link:https://github.com/openshellorg/prohelp[prohelp] library (C mode planned) | prohelp-cli
| New D CLI with subcommands and flags | **prohelp-cli** + link:https://opendlang.org/library/arsd.cli.html[arsd.cli] (or similar) + prohelp | Raw intercept only
| Author/preview help.sdl before shipping | `prohelp` executable from prohelp repo | —
| Global `help <command>` on PATH | `help` binary from prohelp (`dub build -c help`) | —
| Smoke-test this bridge package | `dub build -c demo` → `prohelp-cli-demo` | —
| Python/Rust/Go CLI | Prohelp via FFI + your framework (Click, clap, cobra, …) | prohelp-cli (D-only bridges)
|===

== Quick start (D + arsd.cli)

[source,d]
----
import arsd.cli;
import prohelp.intercept;

class App {
    void create(string[] files) { /* ... */ }
}

int main(string[] args) {
    if (prohelp.intercept(args)) return 0;
    return runCli!App(args);
}
----

Help triggers (`?`, `help`, `-h`, …) are handled by Prohelp. Execution (`mytool create --file x`) is handled by arsd.cli. See link:docs/modules/explanation/pages/arsd-cli-bridge.adoc[How Prohelp fits arsd.cli] for the full model, folder conventions, and roadmap (UDA codegen, `runCli` wrapper).

== Demo binary

[source,shell]
----
dub build -c demo
./prohelp-cli-demo ?
----

== Dependencies

* link:https://github.com/openshellorg/prohelp[prohelp] — progressive help library
* link:https://opendlang.org/library/arsd.cli.html[arsd.cli] — OpenD CLI router (add to your app when implementing; not yet a hard dependency of this package scaffold)
